## What v1.1.1 Intended

v1.1.1 was not meant to be the final runtime. Its own files repeatedly say it is a reentry-safe Phase 5 launch bridge.

The intended true runtime/kernel was expected to provide:

- ledger-first execution
- no floating state
- package grounding before action
- context slice loading
- dependency-aware loading
- active step and return point tracking
- branch-aware anchoring
- deferred branch handling
- line-level or semantic-unit precision escalation
- user authority at decision boundaries
- no silent promotion
- closeout before risky transition
- package/content validation beyond file counts
- a GPT-emulatable runtime model that can later move to plugin/local-app architecture

The most concise old-version formula is:

`ledger-slice execution + dependency-aware loading + user-confirmed gates`

## Major Gaps Against v1.1.1 Intent

### 1. Reentry Grounding Proof Gate

v1.1.1 requires the assistant to prove which package, prompt, and required files were loaded before it can classify, mutate, recommend, package, or continue.

Current rebuild status: missing as a first-class runtime/kernel feature.

Closest current support:

- CUE workspace validation
- replay validation manifests
- checkpoints and handoffs

Missing capability:

- a `ReentryGroundingProof` model
- required file list validation
- loaded/partial/not-read tracking
- stop condition when grounding is incomplete
- active package/prompt verification

Recommended task: add a reentry grounding proof model and runtime validator.

### 2. Ledger-Slice Execution

v1.1.1 treats the ledger as operational memory, not commentary. Every meaningful step must define the active step, ledger slice, dependencies, loaded sources, update, verification, and return point.

Current rebuild status: partially covered but not equivalent.

Closest current support:

- artifact ledger
- checkpoints
- handoffs
- mutation rollback records

Missing capability:

- process ledger entries
- active step ledger slices
- semantic unit / bounded item state
- required update-before-continue gate
- verification state per step
- drop-expanded-context marker

Recommended task: add a process ledger / active-step ledger-slice model separate from artifact provenance.

### 3. Context Dependency Map

v1.1.1 distinguishes structural dependencies from contextual dependencies and requires step-specific files-to-load and files-not-to-load.

Current rebuild status: partially covered at a simpler path level.

Closest current support:

- task `allowedContext`
- task `blockedContext`
- context router
- project graph

Missing capability:

- typed structural dependencies
- typed contextual dependencies
- active-step load plans
- files-not-to-load per step
- dependency expansion rules
- semantic-unit dependency checks

Recommended task: extend context routing into a typed context dependency map.

### 4. Branch-Aware Anchoring / Return Model

v1.1.1 requires branch state, return points, branch purpose, success condition, and close before returning to active work.

Current rebuild status: missing.

Closest current support:

- handoff records with next valid step
- deferred items
- checkpoints

Missing capability:

- branch records
- return point records
- active branch vs deferred branch distinction
- branch success conditions
- branch closeout validation
- resume criteria

Recommended task: add branch-aware anchoring and return-point kernel records.

### 5. Closeout / Return-Point Protocol

v1.1.1 requires closeout verification before phase transitions, new chats, large shifts, or risky changes.

Current rebuild status: partial and scattered.

Closest current support:

- checkpoints
- handoffs
- replay validation
- current-state report

Missing capability:

- closeout record type
- closeout gate
- phase-transition verification
- ledger sync check
- deferred branch anchoring check
- next-step update check

Recommended task: add a closeout/return-point protocol model and runtime validator.

### 6. Deferred Work Unification

v1.1.1 distinguishes deferred items that directly feed Phase 5 from deferred work that must remain out of first scope.

Current rebuild status: simple deferred model only.

Closest current support:

- `DeferredItem` with reason, resume timing, evidence, and status

Missing capability:

- deferred category
- phase relation
- direct input vs not-first-scope distinction
- deferred dependency map
- deferred activation rule
- explicit "known but not executable" state

Recommended task: extend deferred records with phase scope, activation rule, and dependency classification.

### 7. Package / Reentry Synchronization

v1.1.1 treats package state, active reentry prompt, manifest, checksums, path limits, and content-level packaging as a single safety surface.

Current rebuild status: missing.

Closest current support:

- task/state CUE validation
- artifact chains
- runtime-flow visual map

Missing capability:

- package manifest model
- checksum manifest model
- path length gate
- package active prompt verification
- content-level audit gate
- accepted-stable package operation

Recommended task: add package/reentry manifest and checksum validation.

### 8. Precision Escalation Gate

v1.1.1 requires line-level or semantic-unit comparison when identity, authority, runtime, ledger schema, integration, or reentry surfaces are affected.

Current rebuild status: not modeled.

Closest current support:

- tests
- replay validation
- artifact evidence

Missing capability:

- risk classifier for precision escalation
- source comparison mode
- semantic-unit review record
- evidence that comparison happened before decision

Recommended task: add a precision escalation / deep comparison gate.

### 9. User Authority Decision Points

v1.1.1 says the user is decision authority and decisions changing identity, authority, structure, promotion state, integration status, or deferred classification require explicit user choice.

Current rebuild status: partially covered.

Closest current support:

- approval records
- approval-gated mutation planning/application

Missing capability:

- typed decision point records
- decision boundary classifier
- user choice artifact
- "assistant may not decide" blocker
- distinction between approval to perform action and decision authority over meaning/state

Recommended task: add a user decision boundary model.

### 10. Historical / Superseded Surface Boundary

v1.1.1 has strong rules for active prompt vs historical prompt, recovered/pass3 evidence, deferred material, reference reports, runtime starters, and old package material.

Current rebuild status: partly represented as operating rules, not enforced.

Closest current support:

- archive blocked context
- old material treated as reference only
- artifact chain task scope

Missing capability:

- historical/superseded surface classifier
- active authority surface registry
- recovered material classification trace
- no-promotion-from-reference gate

Recommended task: add an authority surface registry and historical material classifier.

## Highest-Risk Missing Features

The top priority gaps are:

1. Reentry grounding proof gate.
2. Ledger-slice / active-step operational memory.
3. Typed context dependency map.
4. Branch-aware anchoring and return points.
5. Closeout / return-point protocol.

These five form the practical Phase 5 runtime/context-load architecture that v1.1.1 was pointing toward. Without them, the rebuild is a strong governed task kernel, but not yet the true ThinkIO runtime that can resume complex work without chat-memory overload.

## Bottom Line

`thinkio-rebuild` now implements many of the enforceable pieces that v1.1.1 wanted: governed tasks, validation, approvals, artifact provenance, checkpoints, replay checks, and guarded mutations.

What it still lacks is the higher-order runtime discipline that v1.1.1 was designed to launch: a package-grounded, ledger-sliced, dependency-aware, branch-safe context runtime that can keep GPT from overloading while still preserving ThinkIO's authority and continuity rules.
